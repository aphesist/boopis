## 1. Repository organisation (item a)

Root `AGENTS.md` is a hub with a routing table to per-area AGENTS.md files (`agent/`, `hermes_cli/`, `gateway/`, `tools/`, `plugins/`, `tui_gateway/`, `apps/desktop/`, `skills/`, `cron/`, `pm/`, `providers/`). It states two invariants: **per-conversation prompt caching is sacred** (no mid-conversation toolset swaps, memory reloads, prompt rebuilds) and **"the core is a narrow waist; capability lives at the edges"** (extend via CLI command + skill, service-gated tool, plugin, MCP server, last a core tool).

Conventions: topic that outgrows a file becomes `<stem>/` with a facade `__init__.py`; flat `<stem>_<topic>.py` siblings are the legacy shape. Config in `~/.hermes/config.yaml`, **`.env` secrets only** (new `HERMES_*` env vars for non-secret config are explicitly rejected). Never hardcode `~/.hermes`: `hermes_constants.get_hermes_home()`.

Self-registration: tools call `registry.register(name, toolset, schema, handler, check_fn, ...)` at import; any `tools/*.py` with a top-level `registry.register()` is auto-imported by `discover_builtin_tools()`; a tool is only exposed if a toolset names it (`tools/AGENTS.md`). Model providers call `providers.register_provider(ProviderProfile(...))`. Slash commands live in `hermes_cli/commands.py::COMMAND_REGISTRY`. Plugins use `register(ctx)`. Pip plugins use entry-point groups `hermes_agent.plugins` and `hermes_agent.plugin_capabilities` (`hermes_cli/plugins_discovery.py:29-30`) [V].

## 2. Plugin system (item b)

### Manifest
`plugin.yaml` (v1 permanent, v2 additive), parsed by `hermes_cli/plugins_manifest.py::PluginManifest` [V]. Fields: `name, version, description, author, requires_env, provides_tools, provides_hooks, kind` (`standalone` default | `backend` | `exclusive` | `platform` | `model-provider`), `requires_hermes` (e.g. `">=0.21.4"`), `capabilities`, `manifest_version`, `api_version`, `requires_plugins` (advisory, orders load), `python_dependencies`, `config_schema` (drives settings forms), `config_keys`, `license, homepage, tags, emits, listens, provides_locales`, `requires_auth`, `oauth`. **Unknown fields are ignored** (additive contract). `provides_tools/hooks` are metadata; `hermes plugins validate` fails when they drift from what `register()` does, but loading does not depend on them. A second, portable format: Agent Plugins v1 (`plugin.json` + `skills/*/SKILL.md` + `mcp.json`, with a `com.nousresearch.hermes` extension block), loaded by an adapter, skills only + stdio/HTTP MCP (`website/docs/developer-guide/plugins/index.md` "Portable Agent Plugins v1"). Non-Python extension surfaces: MCP servers (`mcp_servers:` in config), gateway hooks (`~/.hermes/hooks/<n>/HOOK.yaml`+`handler.py`, gateway-only), shell hooks (`hooks:` in config), TTS/STT command templates, desktop plugins (`$HERMES_HOME/desktop-plugins/<id>/plugin.js`, separate system).

### Discovery
`hermes_cli/plugins.py` docstring [V]: bundled `<repo>/plugins/<name>/`, user `~/.hermes/plugins/<name>/` (per-profile: `<profile home>/plugins/`), project `./.hermes/plugins/` (opt-in `HERMES_ENABLE_PROJECT_PLUGINS`), pip entry points. Later wins on collision. A directory plugin needs `plugin.yaml` + `__init__.py` with `register(ctx)`. Standalone plugins are **opt-in** via `plugins.enabled: [...]` / `plugins.disabled` in config.yaml (`hermes plugins enable|disable|install|update|doctor|validate|capabilities`). Memory providers and context engines are single-select (bundled-first); model providers multi-register, selected by `model.provider`. `discover_plugins()` runs as a side effect of importing `model_tools.py`.

### Registration API (`hermes_cli/plugins_context.py::PluginContext`) [V]
`register_tool(name, toolset, schema, handler, check_fn, requires_env, is_async, description, emoji, override)`, `register_hook(name, cb, hold_stream=)`, `register_middleware(kind, cb)`, `register_command` (in-session slash), `register_cli_command` (argparse subtree), `register_rpc(name, handler)` + `emit_to_session(sid, event, payload)` (plugin<->frontend channel, see 5), `register_system_prompt_section(id, fn, position="after_memory", max_chars<=4000)`, `register_session_env`, `register_approval_transport`, `register_context_engine`, `register_memory_provider`, `register_platform`, `register_auxiliary_task`, `register_redaction_patterns`, `register_locale[_dir]`, `register_{image_gen,video_gen,web_search,browser,terminal_environment,tts,transcription,delegation}_provider`, `register_secret_source`, `register_skill`, `register_dashboard_auth_provider`, plus `dispatch_tool(name, args)` (full pipeline: approvals, redaction, budgets), `call_mcp`, `inject_message`, `ask_choice`, `llm` (host-owned LLM access with a trust gate), `get_config/set_config`, `state`, `profile_name`, `has_capability`, `has_plugin`, `spawn_task`, `on_unload`, `emit/subscribe` (plugin event bus). Model providers use `providers.register_provider(ProviderProfile)` at import, not `ctx`. **There is no `ctx` method to disable a toolset or hide a built-in tool.** [V: grepped the full method list]

### Hooks (`hermes_cli/plugins.py::VALID_HOOKS`, 48 names, identical on v0.23.2 and main) [V]
Tool/LLM: `pre_tool_call`, `post_tool_call`, `transform_tool_result`, `transform_terminal_output`, `pre_llm_call`, `post_llm_call`, `transform_llm_output`, `pre_verify`, `pre_api_request`, `post_api_request`, `api_request_error`, `pre_auxiliary_call`, `post_auxiliary_call`, `transform_api_error_classification`, streaming observers `on_stream_start/delta/end`, `on_interim_message`.
Session: `on_session_start`, `on_session_open`, `on_session_end`, `on_session_finalize`, `on_session_reset`, `on_session_delete`, `post_compaction`, `agent_loop_stopped`, `subagent_start`, `subagent_stop`, `on_skill_lifecycle`, `post_curator_run`.
Approvals/input: `pre_approval_request`, `post_approval_response`, `on_human_input_request`, `on_human_input_resolved`.
Gateway/other: `pre_gateway_dispatch`, `post_gateway_admission`, `gateway_platform_event`, `pre_command`, `pre_transcription`, `on_room_member_activity`, 7 `kanban_*`/`on_kanban_*`.
Middleware kinds (`hermes_cli/middleware.py::VALID_MIDDLEWARE`): `tool_request`, `llm_request`, `tool_execution` (wraps call, single-use `next_call`), `llm_execution`; schema tags `hermes.middleware.v1`, `hermes.observer.v1`.

Payloads (website/docs/user-guide/features/hooks.md table; signatures are inspected, callbacks without `**kwargs` get only declared fields):
- `pre_tool_call(tool_name, args, task_id, session_id, conversation_id, tool_call_id, turn_id, api_request_id, middleware_trace)`. Returns `{"action":"block","message"}` (veto), `{"action":"approve","message","rule_key"}` (escalate to the human approval gate), or `{"action":"modify","args":{...}}` (shallow-merge). block > approve. **Fails closed** on exception/timeout (default `plugins.hook_callback_timeout` 30s, max 600).
- `post_tool_call(tool_name, args, result, task_id, session_id, conversation_id, tool_call_id, turn_id, duration_ms, status, error_type, error_message, ...)`; `transform_tool_result` returns a replacement string.
- `pre_llm_call(session_id, task_id, turn_id, user_message, conversation_history, is_first_turn, model, platform, ...)`: returns context string/`{"context"}` (injected into the user message) or `{"action":"block"}`.
- `pre_/post_api_request`: sanitized `request`/`response`, `usage`, `provider`, `base_url`, `api_mode`.
- `pre_approval_request` / `post_approval_response`: **observers only** (`command, description, pattern_key, session_key, surface`; response adds `choice, decided_by`). Veto goes through `pre_tool_call`.

### Can a plugin ...?
- **Intercept approvals**: yes, two ways. `pre_tool_call` `approve`/`block` directives; and `ctx.register_approval_transport(name, present_fn)`, selected by `security.approval.transport: <name>` (transport gets a redacted request and returns only a decision; exceptions/timeouts deny; `transport_fallback: deny|builtin`). The docs state there is **intentionally no plugin auto-allow/approval-policy callback**, and **hardline blocks (`rm -rf /` etc.) run before any transport and cannot be disabled** even by `approvals.mode: off` (website/docs/user-guide/security.md "Hardline Blocklist"). [D+V for transport]
- **Register a model provider**: yes (`plugins/model-providers/<n>/` or `$HERMES_HOME/plugins/model-providers/<n>/`, `kind: model-provider`, last-writer-wins). The profile can supply its own client object (`create_client`, `auth_type='external_process'`, `base_url='process://...'`, `classify_api_error`, `fetch_models`). See `$OP/claude-subscription-directsdk/__init__.py`.
- **Disable built-in toolsets**: **no**. Overriding an individual built-in is possible: `register_tool(..., override=True)`, but only with `plugins.entries.<id>.allow_tool_override: true` (declared as capability `tools.override`; fails closed with `PluginToolOverrideError`; bundled plugins exempt) (`hermes_cli/plugins_context.py:272`). Hiding tools is done by session/config policy (section 5/6) or `check_fn`.
- Monkeypatching core is unsupported and refused at catalog admission (`hermes plugins validate` "no core override"); `plugins/AGENTS.md`: plugins "MUST NOT" touch core files, and imports outside `hermes_cli/data/plugin_api.json` ("Public plugin API") only warn.

### Isolation and errors
Default `plugins.isolation: in_process`: plugin code runs in the Hermes process with the user's permissions; `register()` crash disables just that plugin (load timeout default 10s), hook exceptions are logged and skipped (except `pre_tool_call` fail-closed). `plugins.isolation: host` runs every non-bundled plugin in a per-profile host process behind a framed-JSON proxy (`hermes_cli/plugin_host*.py`); some ctx methods cannot cross (`plugin_isolation.HOST_UNSUPPORTED_CTX_METHODS`, no `register_cli_command`). Capabilities are consent+audit, not a sandbox.

### Compat contract (the key stability promise)
`plugins/AGENTS.md` + plugins/index.md: **behavioral, additive**; no global `PLUGIN_API_VERSION`; never remove/rename `PluginContext` methods; hook data added as keyword fields; unknown manifest fields ignored; deprecations need a warning, replacement and >= 2 minor releases. **Internal import paths are not API**: Sep 2026 decomposition (PR #102117) broke old paths after a 2026-09-14 window (`ImportError`), and the `hermes_state` shim is scheduled for removal "no earlier than v0.27.0".

### Bundled / official plugins and the hub
- Bundled: listed in section 1 (25+ platform adapters, memory `byterover/retaindb` until Oct 2026 removal, `kanban`, `disk-cleanup`, `security-guidance`, `google_meet`, `hermes-achievements`, `teams_pipeline`...). Policy: no new third-party-product plugins or in-tree memory providers.
- Official out-of-tree repo `NousResearch/hermes-official-plugins` ($OP): `claude-subscription-directsdk, langfuse, homeassistant, spotify, singularity, mcp-serve, memory-wiki, advanced-delegation, agent-importers, bubblewrap, camofox, blender, ...`. `plugin-catalog/claude-subscription-directsdk.yaml` pins it (`sha`, `requires_hermes: ">=0.21.4"`, `tier: official`, `category: models`).
- **claude-subscription-directsdk** (plugin.yaml `kind: model-provider`, `manifest_version: 2`, `config_schema`, `external_dependencies: claude`) is the best worked example for hypotaxis: it registers a `ProviderProfile` whose client spawns the `claude` CLI behind a loopback relay ("Hermes owns tools, approvals and compaction"), classifies errors, supplies model discovery and usage windows, and needs no core change. It proves a Python plugin can **replace the transport of the LLM call entirely**. It is explicitly "experimental".
- **Hub: yes.** `plugin-catalog/` is "the ONLY discovery system for out-of-tree plugins": one YAML per entry, 40-hex SHA pin mandatory, human-merged PR gate, `removed.yaml` kill list, install scanner, `hermes plugins install <name>|owner/repo[#subdir]`, live feed at `hermes-agent.nousresearch.com/docs/api/plugin-catalog.json` (`plugin-catalog/README.md`). Skills have a separate hub (section 3). A "Hermes Marketplace" web page exists with `hermes://` install links (skills.md).

## 3. Skills (item c)

- Format: agentskills.io-compatible `SKILL.md` with YAML frontmatter `name, description (<=60 chars, one sentence), version, author, license, platforms, metadata.hermes.{tags,category,related_skills,fallback_for_toolsets,requires_toolsets,config}` (`skills/AGENTS.md`; `website/docs/user-guide/features/skills.md`). Directory: `SKILL.md` + `references/ templates/ scripts/ examples/ assets/`. Unknown/extra metadata is tolerated; top-level `tags:`/`category:` are mirrored. [D]
- Locations, precedence high to low: project `<git root>/.hermes/skills/` or `.agents/skills/` (needs `hermes skills trust`, scanned, content-hash cached), `~/.hermes/skills/` (source of truth, profile-scoped, seeded from bundled `skills/`), `skills.create_dir`, `skills.external_dirs`; plugin skills are `<plugin>:<skill>`; optional skills installed with `hermes skills install official/<cat>/<skill>`.
- Prompt loading: progressive disclosure. A category-grouped index (names + <=60-char descriptions, ~3k tokens) lives in the system prompt; `skills_list` -> `skill_view(name)` -> `skill_view(name, path)` load on demand; every skill is also a `/slash` command (resolves to a normal user message, no system-prompt mutation). Skills added mid-conversation reach the model as a one-time note, and the system prompt picks them up at the next compaction (cache preservation). [D]
- Learning loop [V `agent/background_review.py`, `agent/curator.py`, `tools/skill_manager_tool.py`]: after turns a daemon thread forks the agent (same prefix cache, tool whitelist) to decide whether memory/skills should be saved (`memory.nudge_interval` 10 user turns, `skills.creation_nudge_interval` 15 tool iterations); the agent can also call `skill_manage(create|patch|edit|delete|write_file|remove_file)`; advisory linter; `skills.write_approval` gates writes. The curator (`hermes curator ...`, `~/.hermes/skills/.usage.json`) only touches `created_by: "agent"` skills, archives (never deletes) stale ones, pre-run tar.gz backups. `post_llm_call` carries `review_signals` for plugins that want the same cadence. `/learn` authors skills from sources.
- Hub (`tools/skills_hub*.py`): `hermes skills search|install|update|tap add`, sources `official`, `skills-sh`, `well-known`, `github`, `clawhub`, `lobehub`, `browse-sh`, direct URL; security scan with trust levels, lock file `skills/.hub/lock.json`; custom taps are GitHub repos.
- Memory is separate: `~/.hermes/memories/MEMORY.md` (agent notes) and `USER.md` (user profile), frozen snapshot injected at session start; `SOUL.md` is prompt slot #1; project context file priority `.hermes.md` > `AGENTS.md` > `CLAUDE.md` > `.cursorrules` (`website/docs/user-guide/which-file-does-what.md`). Note: hypotaxis's own CLAUDE.md/AGENTS.md will be read by Hermes if present.

## 5. Gateway / RPC protocols (item e)

Hermes has **three** programmatic surfaces (`website/docs/developer-guide/programmatic-integration.md`), all driving the same `AIAgent`:

### 5.1 `hermes-gateway-v1` (JSON-RPC over WebSocket; the Desktop/TUI path). Recommended.
- Constant `CANONICAL_GATEWAY_PROTOCOL = 'hermes-gateway-v1'` (`gateway/session_contract.py`). Endpoint `ws://127.0.0.1:<port>/api/ws`. Frames are JSON-RPC 2.0 text; the server also sends requests (`id: "srq-<n>"`). Events are notifications `{"jsonrpc":"2.0","method":"event","params":{"type","session_id","payload","seq","replay_epoch","execution_generation"?,...}}` (`gateway/session_events.py:79`).
- **Bootstrap (public client contract, `website/docs/developer-guide/gateway-internals.md`):** run `hermes gateway attach --json [--start|--recover]` -> `{"url","protocol","protocols":["hermes-gateway-v1","hermes-gateway-ticket.<ticket>"],"ticket","endpoint":{profile_id,instance_id,capabilities,code_sha}}`. Dial `url` from loopback, **with no `Origin` header**, offering `protocols` as WebSocket subprotocols; ticket is single-use, 30 s, per profile+instance. Or skip Python: speak the **local control socket** directly (one JSON line request `{"protocol":1,"id":1,"verb":"resolve-profile"|"identify"|"session-ticket","params":{...}}`; POSIX 0600 Unix socket `gateway.sock` / `gateway.sock.path` pointer; Windows named pipe `hermes-gateway-<sha256[:16]>` needing SID verification). Replayable vectors: `apps/shared/src/node/control-socket.vectors.json` (`tests/gateway/test_control_socket_vectors.py`). `hermes gateway ensure --json` exit codes 0/2/3/4/5/6/7 (ready, invalid, incompatible, auth/profile mismatch, deadline, draining, inaccessible). The daemon is per-profile, started on demand, **idle-exits**, and outlives `hermes update` (compare `client_code_sha` vs `endpoint.code_sha`; `hermes gateway restart`).
- **Handshake:** `runtime.describe` -> `{instance_id, profile_id, authority_epoch, capabilities[], session_create:{sources[],parameters[]}, skin}`; gate on `capabilities` (`plugin-rpc-v1`, `session-list-cursor-v1`, `session-client-v1` ...). On WS send `client.capabilities {"server_requests": true}` after `gateway.ready` or legacy-style server requests are refused (documented as breaking for old WS integrations).

## 6. Model providers and caching (item f)

- Three API modes: `chat_completions` (OpenAI-compatible client), `codex_responses`, `anthropic_messages` (native Anthropic; `agent/anthropic_adapter.py`), plus `bedrock_converse`, gemini-native adapters (`agent/*_adapter.py`). Providers are `ProviderProfile` objects (`providers/base.py`) selected via `hermes_cli/runtime_provider.py` -> `(api_mode, api_key, base_url)`; hooks `prepare_messages, build_extra_body, build_api_kwargs_extras, fetch_models, create_client, classify_api_error`.
- **Prompt caching** (`agent/prompt_caching.py` docstring [V]): "4 cache_control breakpoints: the static system prefix, the end of the system prompt, and the last 2 non-system messages" (without a static prefix: one system + last 3), one shared TTL (5m/1h); envelope layout for OpenAI-compatible routes (OpenRouter/Nous/LiteLLM, with LiteLLM-specific tool-part handling), native inner-block layout for `anthropic_messages`; one-shot requests (compression, titles) are not marked. Per-model override: `providers.<n>.models.<id>.prompt_caching: true|false` (configuring-models.md). Prompt tiers `stable -> context -> volatile` (`agent/prompt_builder.py`, `system_prompt.py`).
- **One custom endpoint as the only provider: yes by config alone** [V docs+code]: `model: {provider: custom, default: <id>, base_url: http://127.0.0.1:PORT/v1, api_mode: chat_completions}` + key in `.env` (or `providers.<name>.{api, api_key, transport, models}`), or per-session `session.create {provider, model, base_url, api_key}`. Caveats: (1) **auxiliary calls** (titles, compression, vision, smart approvals, curator, background review) default to `provider: auto` = main model and are *skipped with a warning* if the main route cannot serve them and no `fallback_providers` is set, so set them explicitly (`auxiliary.*`), or the gateway must serve them; (2) the gateway must accept OpenAI `tools[]`, streaming, and optionally `cache_control` parts; (3) model discovery probes `/models` unless `discover_models: false`; (4) I did not verify that no other background network calls happen at startup (models.dev catalog refresh in `agent/models_dev.py`, update checks `updates.check`, `hermes plugins` catalog refresh) [?]. A plugin `ProviderProfile` with `create_client` (as in `$OP/claude-subscription-directsdk`) is the alternative when the "gateway" is not HTTP.

## 7. Tool execution (item g)

- **Code kernel** (`tools/code_kernel.py`, 1084 lines; `tools/code_execution_tool.py`; tool `execute_code`, toolset `code_execution`) [V]: persistent **per-conversation Python** child ("one child per (owner, mode, interpreter, cwd, tool-set), one code cell per call, state survives across calls"); wire = JSON line per cell on stdin, framed replies with a random sentinel; cell is a **synchronous `exec(compile(code, "<cell>", "exec"), GLOBALS)`**: no top-level `await`, no async stubs (grep finds no async in the runner; stubs return dicts). Timeout (default 300s) or interrupt kills the process tree and **drops state**; limits 50 tool calls/cell, 50 KB stdout (spilled to `cache/exec`), LRU `max_session_kernels: 4`, idle reap 1800s; `reset=true` clears. Local backend: Unix socket (loopback TCP on Windows); remote backends use `code_kernel_remote.py` or per-call script ship. Child env is scrubbed.
- **Can it call Hermes tools: only a fixed 7.** `from hermes_tools import ...` stubs are generated from `SANDBOX_ALLOWED_TOOLS = {web_search, web_extract, read_file, write_file, search_files, patch, terminal}` intersected with the session's enabled tools (`tools/code_execution_tool.py:40,598`); the RPC server rejects any other name (`tools/code_execution_rpc.py:100`) and dispatches through `model_tools.handle_function_call`. Plugin tools, `process_manage`, `delegate_task`, `browser_*`, `memory` etc. are **not reachable**, and the whitelist is a module constant, not extensible by plugin. [V]
- **LSP** (`agent/lsp/`, `website/docs/user-guide/features/lsp.md`): real language servers (pyright, gopls, rust-analyzer, ts-language-server, clangd, ~20 more) as background subprocesses, gated on git-workspace detection, whose `publishDiagnostics` feed only the **post-write lint delta of `write_file`/`patch`** (new diagnostics appended to tool result `lsp_diagnostics` or the next result; a pre-finish wait <=5s). There is **no agent-callable LSP tool** (no goto-def/references/rename) in `tools/` [V by listing]. Config under `lsp:`.
- **Background processes:** `terminal(background=True, notify_on_complete=True)` + `process_manage` (list/poll/wait/kill/handoff; `tools/process_registry*.py`), checkpoint/recovery, completion notifications re-enter as synthetic turns; RPC `process.list/kill/stop`, event `agent.terminal.output`.
- **Subagents:** `delegate_task` (`tools/delegate_tool*.py`): single or batch (`delegation.max_concurrent_children` default 3), `background=true`, roles `leaf|orchestrator` (`max_spawn_depth` 2), per-task `toolsets`, optional model/profile route via a delegation provider plugin (`ctx.register_delegation_provider`), hooks `subagent_start/stop`, RPC `subagent.list/tail/steer/interrupt`, lifecycle API (`subagent-lifecycle-api.md`). Background subagents are not stopped by turn interrupts, only by `/stop`.
- **Worktrees:** `/worktree new <name>` and `hermes -w` (branch `hermes/<name>` under `<repo>/.worktrees/`), plus opt-in `delegation.worktree_isolation` giving each child `<repo>/.worktrees/subagent-<id>` on branch `hermes-subagent/<id>`, local backend only, archived to `refs/hermes/archive/<tree>` (`tools/subagent_worktree.py`). Checkpoints/rollback (`rollback.*` RPC).
- **Sandboxes:** `tools/environments/{local,docker,ssh,modal,managed_modal,daytona,vercel_sandbox}.py` with a shared ABC and name->variant table in `tools/terminal_tool_backends.py`; plugin backends via `ctx.register_terminal_environment_provider`. Docker is off for cwd-mount by default (`docker_mount_cwd_to_workspace: false`); `HERMES_WRITE_SAFE_ROOT` optional write sandbox. MCP: `mcp_servers:` stdio/HTTP, per-server trust/spend limits.

## 8. Updates (item h)

- `hermes update` for managed source checkouts. Official checkouts track the **stable channel**: latest non-draft, non-prerelease `vX.Y.Z` GitHub release at its exact commit (never commit-by-commit); `hermes update --set-channel main` follows `main` (`website/docs/getting-started/updating.md`). PM prepares dependencies (`hermes pm lock|repair|doctor`, `uv.lock`, exact `==` pins, no raw pip/uv in a Hermes env), then restarts gateways. Pre-update backup of config/.env/auth/profile DBs. Packaged installs update by their own owner: Electron `electron-updater` (macOS), App Installer (MSIX), Docker image, Nix, Termux APT. Passive check can be disabled: `updates.check: false`.
- Release process: `scripts/release.py release --commit <sha> --bump patch` creates `rc.<N>-vX.Y.Z` attempt refs, builds lanes (source, Docker, Nix, PM bundle, Windows, signed packages), then a final `vX.Y.Z` receipt tag (`stable-releases.md`). Cadence in section 0.
- **Stable API promise:** only the plugin compat contract (section 2) and the "internal paths are not API" rule. The gateway wire is generated/contract-tested but not covered by a written compatibility promise [?]. A running gateway can outlive `hermes update`, so a host needs the `code_sha` mismatch check.

## 9. apps/desktop (item i)

- Exists; **Electron** (`main: dist/electron-main.mjs`, `electron-builder`, node >=26, pnpm workspace) + React + Vite + nanostores + `@assistant-ui/react`; TS contract and client in `apps/shared` (`@hermes/shared`, `JsonRpcGatewayClient`, generated `gateway-contract.generated.ts`). Backend is **not owned**: `hermes gateway ensure --json`, tickets over a private preload IPC, one multiplexing owner per home; remote connections via SSH / URL+token / Cloud use the same wire (`apps/desktop/src/AGENTS.md`). Variants: source-built, bundled (`dist:bundled` stages Python payload via `scripts/build/python.mjs`), canary/commit builds as separate apps. `apps/bootstrap-installer` is a **Tauri 2** installer (Hermes Setup), not the app.
- `apps/desktop/AGENTS.md` (engineering guide): three authorities (Electron = machine, renderer = experience, backend = work); "decide state by authority", server truth is cached not owned, one ordered ladder per seam (versions, profiles, local/remote), compat with older backends, "the shell's internal registries are composition seams, not a public plugin ABI". `DESIGN.md`: flat not boxed; borderless elevation (`shadow-nous` + `--stroke-nous` hairline); one primitive per concern (one `Button`, one `SearchField`...); **tokens not literals** (`--ui-*`, `--theme-*`); style lives in the primitive; intent before automation (never open panes/move focus because a tool produced something); immediate optimistic feedback; chat is the home surface, pages durable, overlays short tasks, panes working context, projects own cwd.
- Desktop plugin SDK (`website/docs/developer-guide/desktop-plugin-sdk.md`): a single ESM `plugin.js` importing only `@hermes/plugin-sdk` (panes, routes, sidebar nav, status bar, palette, keybinds, themes, `host.request` = gateway RPC, scoped `/api/plugins/<id>` REST), dropped in `$HERMES_HOME/desktop-plugins/<id>/` or shipped as `desktop/plugin.js` inside a Python plugin ("unified package"), hot-reloaded, validated by `hermes plugins validate` "desktop surface" rules.
- **Model for hypotaxis?** The architecture (authority split, gateway as the only agent seam, capability-style bridge, canonical contract consumed from generated types) is a good template. The *code* is React+Electron-specific, so a Tauri host cannot reuse `desktop/plugin.js` without embedding the same SDK in a webview. Hermes plugins' Python halves work; their desktop halves are a separate extension surface hypotaxis must decide about.

## 10. Install footprint (item j)

- `pyproject.toml`: `requires-python = ">=3.11,<3.15"` but every core dep is pinned `==X.Y.Z; python_version >= '3.14'` and the comment says "we *only* support 3.14" (older Pythons are allowed only to finish an update). Entry scripts `hermes`, `hermes-agent`, `hermes-acp`. Core deps exact-pinned (openai, httpx, rich, pydantic, jinja2, requests, ruamel.yaml, firecrawl-anydoc, croniter, fastapi/uvicorn for serve...). Extras are many (`anthropic, modal, daytona, vercel, mcp, acp, messaging, voice, computer-use, browser/playwright, bedrock, vertex, web, pty, all, ...`).
- **PM owns the toolchain** (`pm/lock.json`, `website/docs/reference/package-management.md`): pinned Python, Node, npm, pnpm, ripgrep, FFmpeg, uv bootstrap, plus browser/computer-use tools; `uv` is used only to bootstrap then replaced by PM. - First run: `hermes setup [--non-interactive|--portal|--quick]` / `hermes model` (writes the `model:` mapping; empty string sentinel before that), seeds bundled skills and `SOUL.md`, optionally imports from OpenClaw/Claude Code/Codex/Cursor. # Implications for hypotaxis

(Opinions; evidence labels as above.)

### Cleanest way for a Rust/Tauri host to drive unmodified Hermes
1. Install/own the Hermes tree through Hermes's own mechanisms (PM + `install.sh` or a pinned release; stable channel `vX.Y.Z`). Pin a minimum via `requires_hermes` and refuse older. Do not vendor-patch.
2. Use **`hermes gateway ensure|attach --json`** (or the documented control socket) to start/find the per-profile gateway, then a Rust WebSocket client speaking **`hermes-gateway-v1`** (no `Origin`, subprotocol ticket, new ticket per reconnect). Generate Rust types from `apps/shared/src/gateway-contract.openrpc.json` (262 methods, notifications, server requests); vendor it per Hermes version and diff it on update. Always run `runtime.describe` first and gate features on `capabilities`.
3. Give hypotaxis its **own `HERMES_HOME`/profile** (never a user's) so its shim, config and `skills/` do not collide; one agent process per home.
4. Treat `session.create` as the policy surface: `provider/model/base_url/api_key` -> the hypotaxis gateway, `toolsets` -> only the shim toolset(s), `skills`, `cwd`, `source`.
5. Embed ACP only as a secondary compatibility face (editor integrations); skip the HTTP API server (no steer/approval-level fidelity for unattended sessions, adds a port).

### What must be a Hermes plugin (the "shim")
A normal `kind: standalone` plugin in `<profile>/plugins/hypotaxis/` (`plugin.yaml` v2 + `__init__.py:register(ctx)`):
- the 3 hypotaxis tools via `ctx.register_tool(toolset="hypotaxis", ...)` (plugin toolsets are discovered automatically; handlers get `(args, **kw)` and **return a JSON string**; `check_fn` hides them when the host is absent);
- `pre_tool_call` (block/approve/modify) as the host's policy/permission and path-rewrite point; `post_tool_call`/`transform_tool_result` for telemetry and result shaping; `pre_llm_call`/`ctx.register_system_prompt_section` for host context (prefer the section API for cache safety);
- `ctx.register_rpc("name", ...)` + `ctx.emit_to_session` as the shim<->host side channel (appears as `plugin.hypotaxis.<name>` on the same socket; gate on `plugin-rpc-v1`);
- optionally `ctx.register_approval_transport("hypotaxis", ...)` + `security.approval.transport: hypotaxis` so dangerous-command prompts land in the host UI without the event path;
- optionally a `ProviderProfile` (model-provider plugin) if the host's gateway is not a plain OpenAI-compatible endpoint (use the `$OP/claude-subscription-directsdk` pattern).
Declare `capabilities:` truthfully (`tools.override` only if needed), `requires_hermes`, and keep imports to `hermes_cli/data/plugin_api.json`. Run `hermes plugins doctor/validate --ci` in hypotaxis CI against each new Hermes tag.

### Conventions hypotaxis should copy for its own extension points
- Manifest: `plugin.yaml` with `name, version, description, kind, requires_hermes, provides_tools, provides_hooks, capabilities, requires_env, config_schema, manifest_version, api_version, requires_plugins, python_dependencies, tags`; ignore unknown fields; keep v1 forever. Also accept the portable `plugin.json` (Agent Plugins v1) for skills/MCP.
- Discovery and layout: `<home>/plugins/<name>/{plugin.yaml,__init__.py}`, `<home>/skills/<category>/<skill>/SKILL.md`, `<home>/hooks/<name>/{HOOK.yaml,handler.py}`, `<home>/desktop-plugins/<id>/plugin.js`, `<project>/.hermes/{plugins,skills}` and `.agents/skills` (trust-gated), enable lists in `plugins.enabled`. The hypotaxis host should *read the same dirs and config keys* rather than invent parallel ones, so a Hermes plugin dropped there is seen by both sides (it is Hermes that loads Python plugins; hypotaxis only needs to surface them, e.g. through `plugins.list`/`plugins.manage` RPC).
- Hook names: reuse Hermes's exact names and kwargs semantics (`pre_tool_call` directive shape, `**kwargs` forward-compat, signature inspection, fail-closed policy hooks, 30 s timeout). Host-side hooks that mirror Hermes ones should keep the same names so code is portable.
- Registry style: self-registration at import, `check_fn` availability, tool results as JSON strings, toolsets as the exposure unit, `<plugin>:<skill>` namespacing, SHA-pinned catalog entries for distribution.
- Wire style: JSON-RPC 2.0 + `event` notifications with `seq/replay_epoch`, capability strings in a `describe` call, generated OpenRPC as the source of truth.
- UI: `apps/desktop/DESIGN.md` principles (tokens over literals, flat, intent before automation) are a reasonable reference, but hypotaxis should follow its own design rules where they differ.

### Risks
- **Moving target:** ~2 stable releases/week, `main` daily; the gateway wire is migrating (legacy tui_gateway catalog vs canonical authority; 160 methods on an "undecided" legacy path; approvals exist in two shapes). No written wire-compat guarantee found. Mitigate: pin Hermes, regenerate the OpenRPC types per bump, feature-detect, keep a conformance test over the recorded `control-socket.vectors.json` and a smoke session.
- **Python 3.14-only effective support, PM-owned environment, Node/Chromium/ffmpeg footprint**; plugin deps go through PM admission; first run is heavy and network-dependent. A daemon that **idle-exits and can outlive updates** needs lifecycle handling (`code_sha` check, restart).
- **Cannot be switched off:** hardline command blocklist; per-conversation prompt-cache rules (toolsets/memory/system prompt don't change mid-session, so the host must set toolsets at `session.create`); the Hermes system prompt itself (identity/skills index/memory blocks, SOUL.md, AGENTS.md/CLAUDE.md context files) and memory/skill background review (extra LLM calls through the aux client; tune `memory.nudge_interval`, `skills.creation_nudge_interval`, `curator.enabled`); bundled skills seeding (`hermes skills opt-out`); LSP only as write-diagnostics; `execute_code` whitelist.
- **In-process plugins are not sandboxed**, hook timeouts abandon threads, and `pre_tool_call` failures block tools (a buggy shim bricks the agent). `plugins.isolation: host` fixes isolation but drops `register_cli_command` and some ctx methods [D].
- Internal imports break without notice (PR #102117 precedent); stay on `ctx`/ABCs/`plugin_api.json`.

### Assumptions to correct
1. **"The shim can register 3 tools and turn off built-in toolsets."** First half is true. Second half is **false as stated**: no plugin API disables toolsets. Do it from the host at `session.create {toolsets:[...]}` (verified param), or per-profile config (`platform_toolsets`, `hermes tools`), or replace individual built-ins with `override=True` (needs per-plugin `allow_tool_override`/`tools.override` consent), or veto in `pre_tool_call`. I did **not** verify that an explicit `toolsets` list yields an exactly-empty built-in surface (client-surface toolsets `project`/`desktop_ui`/`catalog`, deferred tools via `tool_search`, MCP and kanban gating, inline tools `todo`/`memory`): check `session.info.enabled_toolsets`/`tools.show` and the rendered `tools[]` on a live session [?].
2. **"Hermes can use one custom gateway as its only provider."** **True by config** (`model.provider: custom` + `base_url`, or per-session override), with the caveats in section 6: auxiliary tasks and fallbacks must be pointed at the same gateway or they are skipped, the gateway must be OpenAI-chat-compatible (or declare `transport: anthropic_messages`), and background network calls other than inference were not ruled out [?].
3. **"session.steer exists."** **True** in `hermes-gateway-v1` (needs `execution_generation`, best-effort delivery at the next tool boundary, `unsupported_control` for managed workers). It is not on the ACP surface.
4. **"The code kernel can call Hermes tools."** **Only partly.** Persistent, yes (per conversation, Python only, state lost on timeout/interrupt). Async/await: **no** (sync `exec`, sync stubs). Tool calls: **only 7 whitelisted tools** (`web_search, web_extract, read_file, write_file, search_files, patch, terminal`) over a local RPC into `handle_function_call`; plugin/shim tools are **not** callable from it and the whitelist is not extensible by plugins.
5. Also adjust: there is no "hermes-gateway-v1 over stdio" in the strict sense; stdio is the older `tui_gateway` catalog, and v1 is the WebSocket authority path. LSP is write-diagnostics only, not an agent tool. A third-party Tauri host cannot reuse Hermes desktop `plugin.js` plugins as-is.
