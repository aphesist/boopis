# On-disk extension formats for hypotaxis: compatibility loader spec

Research date 2026-11-18. Sources are fetched primary docs unless marked [UNVERIFIED]. Source code was not read; every "docs vs code" note below is a gap to test against the real binaries, not a finding. Claude Code docs describe v2.1.3xx-era behaviour; version gates are noted where the docs give them.

Doc bases: CC = https://code.claude.com/docs/en/ ; ASK = https://agentskills.io/specification ; CDX = https://learn.chatgpt.com/docs/ (developers.openai.com/codex/* 308-redirects here); GEM = https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/ ; CUR = https://cursor.com/docs/ ; AG = https://antigravity.google/docs/ ; MCP = https://modelcontextprotocol.io/specification/2026-07-28/

## 1. Claude Code

### 1.1 CLAUDE.md and rules (CC memory)
- Locations: managed `/Library/Application Support/ClaudeCode/CLAUDE.md` (mac), `/etc/claude-code/CLAUDE.md` (Linux/WSL), `C:\Program Files\ClaudeCode\CLAUDE.md` (Win); user `~/.claude/CLAUDE.md`; project `./CLAUDE.md` or `./.claude/CLAUDE.md`; local `./CLAUDE.local.md` (gitignored). Plus `~/.claude/rules/*.md` and `.claude/rules/**/*.md` (recursive, symlinks allowed).
- Load: CLAUDE.md and CLAUDE.local.md in cwd and every ancestor at launch; concatenated, ordered filesystem root down to cwd (nearer = later). Subdirectory CLAUDE.md files load lazily when Claude reads/writes/edits a file there. Managed CLAUDE.md cannot be excluded; others via `claudeMdExcludes` (absolute-path globs, arrays merge across layers). Managed content can also come from the `claudeMd` managed-settings key.
- `@path` imports: relative paths resolve against the importing file; absolute and `~/` allowed; recursive, max depth 4; spaces need `\ ` (quoted paths are not imported); skipped inside code spans and fenced blocks. Imports resolving outside the working dir in project files trigger a one-time approval dialog; user-scope files load them without approval.
- `.claude/rules/*.md` frontmatter: `paths:` (glob list) makes a rule load only when matching files are in use. Rules without `paths` load at launch.
- AGENTS.md: since v2.1.277, read when no CLAUDE.md/.claude/CLAUDE.md/CLAUDE.local.md exists in cwd or above (default `claude-md-or-agents-md`); also `.claude/AGENTS.md`; `@` imports work inside it. Not read: `AGENTS.local.md`, `AGENTS.override.md`, anything under `.agents/`. Mode `claude-md-and-agents-md` loads both (CLAUDE first per directory, de-duplicated). Setting lives in `pluginConfigs` under `cc-plugin-agents-md@builtin`.
- Auto memory exists (first 200 lines/25KB loaded) but is Claude-written and out of loader scope.

### 1.2 Settings (CC settings, permissions, managed-settings)
- Files (precedence high to low): managed (`managed-settings.json` + `managed-settings.d/*.json` merged alphabetically, in `/Library/Application Support/ClaudeCode/`, `/etc/claude-code/`, `C:\Program Files\ClaudeCode\`; also macOS profile domain `com.anthropic.claudecode`, Windows `HKLM\SOFTWARE\Policies\ClaudeCode` value `Settings`, HKCU, server-managed) > `--settings <file|json>` > `.claude/settings.local.json` > `.claude/settings.json` > `~/.claude/settings.json` (`CLAUDE_CONFIG_DIR` relocates `~/.claude`). Strict JSON (no comments). `~/.claude.json` is separate: MCP local/user scope, trust state.
- Within managed tier the first source with a policy key wins (remote > MDM/registry > files > HKCU) unless `managedSourcesBehavior: "merge"`.
- Merge: scalars from highest scope; arrays (`permissions.allow` etc.) are unioned across files; objects such as `env` merge per key. Exceptions: `fallbackModel`, `modelPicker`, `availableModels` (managed list is authoritative), `modelSettings`. Some keys are ignored from repo files (`permissions.defaultMode` of `auto`/`bypassPermissions`; telemetry env). Project `allow` rules, `additionalDirectories`, `extraKnownMarketplaces`, most `env` wait for folder trust; `deny`/`ask` apply immediately. A few security keys honour the stricter value from any scope (table in CC settings).
- Local file is stored at the git root (worktree: main checkout root); `.claude/settings.json` is read from the primary working directory only (no ancestor walk).
- Keys the loader must model: `permissions{allow,ask,deny,defaultMode,additionalDirectories,disableBypassPermissionsMode,disableAutoMode,denyInsteadOfPrompting,blockReadsOutsideWorkingDirectories,blockWritesOutsideWorkingDirectories}`, `hooks`, `env`, `model`, `outputStyle`, `enabledPlugins`, `extraKnownMarketplaces`, `strictKnownMarketplaces`, `blockedMarketplaces`, `pluginConfigs`, `enableAllProjectMcpServers`, `enabledMcpjsonServers`, `disabledMcpjsonServers`, `allowedMcpServers`, `deniedMcpServers`, `managedMcpServers`, `claudeMdExcludes`, `disableSkillShellExecution`, `$schema` (https://json.schemastore.org/claude-code-settings.json). Full key list: CC settings-reference (not fetched; incomplete here).
- Permission rule syntax (CC permissions): `Tool` or `Tool(specifier)`. Evaluation deny > ask > allow, first match wins, specificity irrelevant. Bare `Bash`/`mcp__*` deny removes the tool from context.
  - Bash: glob with `*`; trailing ` *` also matches the bare command (`Bash(ls *)` matches `ls`, not `lsof`); `:*` suffix is legacy-equivalent; compound commands split on `&& || ; | |& & newline` and every part must be allowed, but deny/ask match if any part matches; wrappers stripped (`timeout time nice nohup stdbuf command builtin noglob`, bare `xargs`, known-safe env assignments); no match for `/usr/bin/curl` or `sh -c`.
  - Read/Edit: gitignore syntax; `//abs/path`, `~/p`, `/p` (anchored at the settings source: project root for project files, `~/.claude` for user), `./p` or bare (relative to cwd). Edit covers all file-editing tools; Read deny also blocks Edit/Write on the path. `Write(`, `Glob(`, `Grep(` path rules do not match.
  - `WebFetch(domain:example.com)`; `Tool(param:value)` for deny/ask on any top-level input param (`Agent(model:opus)`, `Skill(skill:name)`); `mcp__server`, `mcp__server__tool`, `mcp__server__prefix_*` (allow requires literal server segment); `mcp__` rules with parentheses are skipped.
  - Modes: `default|acceptEdits|plan|auto|dontAsk|bypassPermissions`.

### 1.3 Hooks (CC hooks; page read to ~char 200k of 294k)
- Config: `{"hooks":{"<Event>":[{"matcher":"...","hooks":[{handler}]}]}}` in any settings file, plugin `hooks/hooks.json` (wrapped in top-level `"hooks"`), skill/agent frontmatter.
- Handler types: `command` (fields `command` or exec-form `command`+`args`, `shell:"powershell"`, `timeout` s, `async`, `if`, `statusMessage`, `onFailure:"block"` v2.1.295+), `http`, `mcp_tool`, `prompt`, `agent` (last two exist; field lists not extracted). SessionStart accepts only command/mcp_tool; Setup only command. Default timeout 600 s (30 s UserPromptSubmit/PreModelSwitch/PostModelSwitch; 10 s MessageDisplay; prompt 30, agent 60). `if` uses permission-rule syntax, tool events only.
- 33 events: SessionStart, SessionEnd, Setup, UserPromptSubmit, UserPromptExpansion, Stop, StopFailure, PreToolUse, PermissionRequest, PermissionDenied, PostToolUse, PostToolUseFailure, PostToolBatch, SubagentStart, SubagentStop, TaskCreated, TaskCompleted, TeammateIdle, InstructionsLoaded, ConfigChange, CwdChanged, DirectoryAdded, FileChanged, WorktreeCreate, WorktreeRemove, PreCompact, PostCompact, PreModelSwitch, PostModelSwitch, Elicitation, ElicitationResult, Notification, MessageDisplay.
- Matcher: empty/`*`/omitted = all; only `[A-Za-z0-9_\- ,|]` = exact name or `|`/`,` list; anything else = unanchored JS regex. FileChanged/StopFailure exact set is `[A-Za-z0-9_|]`. Matched field per event: tool name (tool events, PermissionRequest/Denied); SessionStart `startup|resume|clear|compact|fork`; Setup `init|maintenance`; SessionEnd `clear|resume|logout|prompt_input_exit|other`; Notification type (`permission_prompt|idle_prompt|auth_success|elicitation_dialog`); Subagent* agent type; Pre/PostCompact `manual|auto`; ConfigChange `user_settings|project_settings|local_settings|policy_settings|skills`; FileChanged literal filenames; InstructionsLoaded `session_start|nested_traversal|path_glob_match|include|compact`; Elicitation* server name. No matcher: UserPromptSubmit, PostToolBatch, Stop, TeammateIdle, Task*, Worktree*, MessageDisplay, CwdChanged. MCP tool names: `mcp__<server>__<tool>`; plugin servers `mcp__plugin_<plugin>_<server>__<tool>`.
- Common stdin: `session_id, prompt_id?, transcript_path, cwd, scratchpad_dir?, permission_mode, effort{level}, hook_event_name, agent_id?, agent_type?`. Per event: PreToolUse `tool_name, tool_input, tool_use_id, mcp_server?`; PostToolUse adds `tool_response, duration_ms?`; PostToolUseFailure `error, is_interrupt?`; PostToolBatch `tool_calls[]`; PermissionRequest `tool_name, tool_input, permission_suggestions?`; PermissionDenied `reason`; UserPromptSubmit `prompt`; UserPromptExpansion `expansion_type, command_name, command_args, command_source, prompt`; SessionStart `source, model?, agent_type?, session_title?`; Setup `trigger`; InstructionsLoaded `file_path, memory_type, load_reason, globs?, trigger_file_path?, parent_file_path?`; Stop `stop_hook_active, last_assistant_message, background_tasks, session_crons`; SubagentStop `stop_hook_active, agent_id, agent_type, agent_transcript_path, last_assistant_message`; StopFailure `error, error_details?, last_assistant_message?`; Notification `message, title?, notification_type`; FileChanged `file_path, event`; WorktreeCreate `name`; Pre/PostModelSwitch `from_model, to_model`. Fields for PreCompact, SessionEnd, TaskCreated, ConfigChange, CwdChanged, TeammateIdle: sections exist but were not extracted.
- Exit codes: 0 = success, stdout parsed as JSON only if exactly one JSON object, else plain text (context for some events); 2 = blocking where the event can block (PreToolUse blocks call; UserPromptSubmit/Expansion block prompt; Stop/SubagentStop force continue; TeammateIdle keeps working; TaskCreated rolls back; TaskCompleted prevents; ConfigChange blocks except policy_settings; PreCompact blocks; PreModelSwitch blocks; Elicitation declines; WorktreeCreate/Remove any non-zero fails; PostToolBatch stops loop; PostToolUse/Failure stderr to Claude; PermissionRequest exit 2 NOT honoured, use decision object; many events ignore); other = non-blocking error unless `onFailure:"block"`. Timeout: output discarded; PreToolUse proceeds, PreModelSwitch blocks.
- JSON output: universal `continue` (false stops Claude; for PreToolUse pair with deny), `stopReason`, `suppressOutput` (no effect), `systemMessage`, `terminalSequence` (OSC 0/1/2/9/99/777 or BEL). Top-level `decision:"block"`+`reason` for UserPromptSubmit, UserPromptExpansion, PostToolUse, PostToolUseFailure, PostToolBatch, Stop, SubagentStop, ConfigChange, PreCompact. `hookSpecificOutput{hookEventName,...}`: PreToolUse `permissionDecision: allow|deny|ask|defer`, `permissionDecisionReason` (and, from prior knowledge, `updatedInput` [UNVERIFIED in this pass]); PreModelSwitch allow|deny|ask; PermissionRequest `decision{behavior allow|deny, updatedInput, updatedPermissions[], message, interrupt}`; PermissionDenied `retry`; `additionalContext` (cap 10,000 chars, overflow to file with 2,000 preview) for SessionStart, SubagentStart, UserPromptSubmit/Expansion, PreToolUse, PostToolUse(+Failure), PostToolBatch, Stop, SubagentStop, PostModelSwitch; WorktreeCreate command hooks print the path on stdout, HTTP hooks return `hookSpecificOutput.worktreePath`. Stop-block loop capped at 8 consecutive continuations.
- Env: `CLAUDE_PROJECT_DIR`, `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA`, `CLAUDE_PLUGIN_OPTION_<KEY>`; `CLAUDE_ENV_FILE` (SessionStart/Setup/CwdChanged/FileChanged; `export` lines appended are sourced before each Bash command).
- Docs vs docs: hooks page says ConfigChange `policy_settings` can't be blocked; Notification hooks discard `continue`/`systemMessage`. Gemini and Codex hook event sets are different (see 3, 4).

### 1.4 Skills (CC skills)
- Locations: managed dir `.claude/skills/`, `~/.claude/skills/<n>/SKILL.md`, `.claude/skills/<n>/SKILL.md`, nested `<sub>/.claude/skills/` (on demand), `--add-dir` `.claude/skills/`, plugin `skills/`, synced `~/.claude/skills/synced/`. Same-name: enterprise > personal > project; skill beats `.claude/commands/` file; plugin skills namespaced `plugin:skill`. Reserved: `synced`, `anthropic-skills`.
- Frontmatter (all optional; unknown ignored; bools accept yes/no/on/off/1/0): `name`, `description` (+`when_to_use`, combined cap 1,536 chars in listing; falls back to first body line), `argument-hint`, `arguments` (string|list, named `$name`), `disable-model-invocation`, `user-invocable`, `allowed-tools` (pre-approve for the invoking turn, space/comma/YAML list), `disallowed-tools`, `model` (or `inherit`), `effort` (low|medium|high|xhigh|max), `context: fork`, `agent` (default general-purpose), `background` (default true, fork only), `hooks`, `paths` (glob auto-load), `shell` (bash|powershell), `metadata`, `license`, `compatibility`. Outside Claude Code (claude.ai/API) only name, description, license, compatibility, metadata, allowed-tools allowed.
- Substitution: `$ARGUMENTS`, `$ARGUMENTS[N]`/`$N` (0-based, shell quoting), `$name`, `${CLAUDE_SESSION_ID}`, `${CLAUDE_EFFORT}`, `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT|DATA}` (plugin skills); no placeholder consuming args = append `ARGUMENTS: <v>`; `\$` escapes. Injection `` !`cmd` `` (at line start or after whitespace) and fenced ```` ```! ````; runs before the model sees it, non-zero exit aborts (exit 1 tolerated), `disableSkillShellExecution` disables.
- Activation: description is always in the listing; model loads body on match or user types `/name`; `user-invocable:false` hides from menu; `disable-model-invocation:true` user-only.

### 1.5 Commands (CC slash-commands)
- `.claude/commands/**/*.md` and `~/.claude/commands/`: legacy, merged into skills. Frontmatter = skill frontmatter minus `name` and `paths`. Subdir -> colon name (`frontend/component.md` -> `/frontend:component`). `$ARGUMENTS`, `$N`, `` !`cmd` `` as skills. `@file` reference behaviour: the fetched page was truncated before that section; `@path` in prompts/command bodies is a file mention (Read deny rules apply) [detail UNVERIFIED].

### 1.6 Subagents (CC sub-agents)
- Files `*.md` (recursive) in `.claude/agents/`, `~/.claude/agents/`, plugin `agents/`; `--agents` JSON (`{name:{description,prompt,tools,model,...}}`, `prompt` replaces body; `color`/`experimental` ignored); managed. Priority: managed > `--agents` > project > user > plugin. Identity = `name` only.
- Frontmatter (camelCase, case-sensitive; unknown ignored): `name` (req, <=256, no `:`/leading `-`), `description` (req), `tools`, `disallowedTools` (applied before tools), `model` (sonnet|opus|haiku|fable|full id|inherit), `permissionMode`, `maxTurns`, `skills[]` (preloaded), `mcpServers` (names or inline), `hooks`, `memory` (user|project|local), `background`, `effort`, `isolation: worktree`, `color` (8 names), `initialPrompt`, `autoCompactWindow`, `omitClaudeMd`, `experimental`. Plugin subagents ignore `permissionMode`, `mcpServers`, `hooks`.

### 1.7 Output styles (CC output-styles)
- `~/.claude/output-styles/`, `.claude/output-styles/` (every level between cwd and repo root; nearest wins), managed `.claude/output-styles/`, plugin `output-styles/`. Frontmatter: `name`, `description`, `keep-coding-instructions` (default false), `force-for-plugin` (plugin only). Activated by `outputStyle` setting (case-sensitive; built-ins Proactive, Concise, Explanatory, Learning) or `/output-style`. Effect: replaces the engineering section of the system prompt unless `keep-coding-instructions`; applies to main thread and forks, not other subagents.

### 1.8 .mcp.json (CC mcp)
- `{"mcpServers":{name:{...}}}`. stdio (default when `type` absent): `command,args,env`. `type:"http"` (alias `streamable-http`) `url,headers`; `type:"sse"` (deprecated); `type:"ws"` (header auth only). Common: `headersHelper` (command printing JSON headers, 10 s, runs per connect and on 401/403), `timeout` ms, `oauth{clientId,callbackPort,authServerMetadataUrl(https),scopes(space string)}`. A `url` with no `type` is rejected; `"type":"sdk"` skipped.
- Env expansion `${VAR}` and `${VAR:-default}` in `command,args,env,url,headers`; unset+no default stays literal with a warning; credential vars (ANTHROPIC_API_KEY, NPM_TOKEN, HTTPS_PROXY...) read as empty in remote url/headers. `CLAUDE_PROJECT_DIR` needs `${CLAUDE_PROJECT_DIR:-.}` in project files.
- Scopes: local (`~/.claude.json` per project) > project (`.mcp.json`) > user (`~/.claude.json`) > plugin > claude.ai connectors; whole-entry replacement, no field merge; dedupe by name (scopes) or endpoint (plugins/connectors). `managedMcpServers` outranks all; `managed-mcp.json` gives exclusive control. Project servers require interactive approval (`enableAllProjectMcpServers`/`enabledMcpjsonServers` honoured only from user/managed/`--settings`/untracked local settings; committed settings.json cannot self-approve); `disabledMcpjsonServers` blocks in all modes. `-p`/SDK/cloud sessions load project servers without prompting.

### 1.9 Plugins (CC plugins-reference, plugin-marketplaces, marketplace-reference)
- Layout: `.claude-plugin/plugin.json` (optional) and everything else at plugin root: `skills/`, `commands/`, `agents/`, `hooks/hooks.json`, `.mcp.json`, `.lsp.json`, `output-styles/`, `workflows/`, `themes/`, `monitors/monitors.json`, `bin/` (put on Bash PATH). Root `CLAUDE.md` is NOT loaded. A root `SKILL.md` with no `skills/` loads as one skill.
- plugin.json: only `name` required (kebab-case; no spaces, `@`, `:`, path separators; names starting `claude-`, `anthropic-`, `cc-plugin-` etc. flagged reserved but still load). Optional: `$schema, displayName, version, description, author{name,email?,url?}, homepage, repository, license, keywords, metadata, icon, documentationUrl, supportUrl, privacyPolicyUrl, termsOfServiceUrl, defaultEnabled(true), engines{"claude-code":range}, dependencies[("name"|"name@mkt"|{name,marketplace,version})], userConfig, types, channels, skills, commands, agents, hooks, mcpServers, lspServers, outputStyles, workflows, experimental{themes,monitors,evals}`. Unknown top-level keys stripped (warning); unknown keys inside strict objects (`userConfig` options, `channels`, `lspServers`, `monitors`) are errors.
- Component keys: all paths relative, must start `./`, no `..`, must exist, contained in plugin root. `skills` ADDS to default scan (accepts `"."`); `commands`, `agents`, `outputStyles`, `workflows`, `experimental.themes|monitors` REPLACE their default dir; `hooks`, `mcpServers`, `lspServers` MERGE with default file (later server name wins). `commands` may be an object map `{name:{source|content (exactly one), description, argumentHint, model, allowedTools}}`. `agents` entries are `.md` files only. `mcpServers` accepts `.json`, `.mcpb`/`.dxt` path or https URL, inline map, or array. `hooks` accepts file (with `"hooks"` wrapper), inline event map (no wrapper), or array.
- `userConfig` option: `type` (string|number|boolean|directory|file), `title`, `description` required; `required, default, options(string, v2.1.271+), multiple, sensitive, min, max`. Reach hooks as `CLAUDE_PLUGIN_OPTION_<KEY>`; `${user_config.KEY}` substitutes in MCP/LSP config, exec-form hook `args`, skill/agent bodies (non-sensitive only); forbidden in shell-form hook commands, monitor commands, `headersHelper`.
- Variables: `${CLAUDE_PLUGIN_ROOT}` (installed version dir, changes on update), `${CLAUDE_PLUGIN_DATA}` (`~/.claude/plugins/data/<id>/`, persistent), `${CLAUDE_PROJECT_DIR}`. Resolved inline in hook command/args, MCP command/args/env/url/headers, LSP fields, skill/command/agent bodies. Not present in env of Bash-tool commands.
- Component names namespaced `plugin:name`. Enabled via `enabledPlugins` map keyed `name@marketplace`.
- marketplace.json at `<root>/.claude-plugin/marketplace.json`: required `name` (letters, digits, `. _ -`, starts alnum, no `..`), `owner{name,email?,url?}`, `plugins[]`; optional `$schema, description, version, metadata{description,version,pluginRoot}, forceRemoveDeletedPlugins, allowCrossMarketplaceDependenciesOn, renames`. Unknown keys ignored (validate warns). Reserved marketplace names (claude-plugins-official, anthropic-*, `inline`, `builtin`, `skills-dir`, `synced`, `claudeai-*`...) unless sourced from github.com/anthropics/.
- Plugin entry: required `name`, `source`; optional `description, version (plugin.json wins), category, tags, strict (default true), relevance, dependencies, engines, defaultEnabled, displayName, metadata, headers, headersHelper` and any plugin.json field. Strict: `plugin.json` is authority; entry's `commands/agents/skills/outputStyles/themes` are appended, entry `hooks` replace manifest matchers per event; with `strict:false` plus manifest plus any component field = load failure "conflicting manifests". With no plugin.json the entry is the manifest (entry hooks only inline object form). Entry `mcpServers/lspServers/userConfig/channels` apply only without plugin.json.
- Plugin `source`: relative `"./path"` (or bare name under `metadata.pluginRoot`); objects `{source:"github",repo,ref?,sha?}`, `{source:"url",url,ref?,sha?}`, `{source:"git-subdir",url,path,ref?,sha?}`, `{source:"npm",package,version?,registry?}` (no install scripts), `{source:"archive",url(https),sha256?}`, `{source:"command",command,timeout?,mode?copy|link}`. `sha` = 40-hex, wins over `ref`.
- Marketplace sources (settings `extraKnownMarketplaces: {name:{source:{...}}}`, `strictKnownMarketplaces[]`, `blockedMarketplaces[]`): `url{url,headers,headersHelper}`, `github{repo,ref,path,sparsePaths}`, `git{url,ref,path,sparsePaths}`, `file{path}`, `directory{path}`, `settings{name,plugins,owner}`; policy-only `hostPattern`, `pathPattern`, `skills-dir`, `owner/*`; `npm` parses but does not load. `url` marketplaces cannot use relative plugin sources.
- Cache: installed plugins copied to a plugin cache; `version` in plugin.json pins; local `directory` marketplaces are read in place.

## 2. Agent Skills open standard (ASK)
- Dir `skill-name/SKILL.md` + optional `scripts/`, `references/`, `assets/`. Frontmatter: `name` (req, 1-64, unicode lowercase alnum + `-`, no leading/trailing/double hyphen, MUST equal parent dir name), `description` (req, 1-1024), `license`, `compatibility` (1-500), `metadata` (string->string map), `allowed-tools` (space-separated string; experimental). Progressive disclosure: metadata ~100 tokens at startup, body <5000 tokens/500 lines when activated, resources on demand; references one level deep. Validator: `skills-ref validate` (https://github.com/agentskills/agentskills/tree/main/skills-ref).
- The spec itself defines no discovery path. `.agents/skills/` is a de-facto convention: Codex (`$CWD`, parents to repo root, `~/.agents/skills`, `/etc/codex/skills`), Antigravity (`<ws>/.agents/skills`, legacy `.agent/skills`), Hermes (`<repo>/.agents/skills` after trust). Claude Code does NOT read `.agents/` (memory page) and its `.claude/skills` only. Docs vs spec: CC accepts every spec field but the spec's `name == dirname` and charset limits are not enforced by CC (CC: `name` defaults to dir, "lowercase, hyphens"); CC adds many non-spec keys, so a loader must treat the spec fields as the portable core and all others as ignorable extension keys.

## 3. OpenAI Codex CLI
- AGENTS.md (CDX agent-configuration/agents-md): global in `CODEX_HOME` (default `~/.codex`): `AGENTS.override.md` if present else `AGENTS.md`, first non-empty only. Project: from project root (git root) down to cwd, per directory check `AGENTS.override.md`, `AGENTS.md`, then `project_doc_fallback_filenames`; one file per dir; concatenated root-first with blank lines (nearer later = overrides); stop at `project_doc_max_bytes` (default 32 KiB). Empty files skipped.
- config.toml (CDX config-file/config-reference; page read to ~100k of 166k): user `~/.codex/config.toml`; project `.codex/config.toml` only for `projects.<path>.trust_level="trusted"`; profiles in `$CODEX_HOME/<name>.config.toml` via `--profile` (the `profile`/`profiles` keys are ignored in project config); project config cannot set `model_provider(s)`, `notify`, `openai_base_url`, `otel`; managed requirements (`requirements.toml`, MDM) outrank. `/etc/codex` for config not confirmed.
- `[mcp_servers.<id>]`: stdio `command,args,cwd,env,env_vars,environment_id`; HTTP `url,http_headers,env_http_headers,bearer_token_env_var,http_headers_helper`; `enabled,required,startup_timeout_sec(10),tool_timeout_sec(60),startup_readiness,enabled_tools,disabled_tools,omit_tools_from,supports_parallel_tool_calls,default_tools_approval_mode(auto|prompt|writes|approve),tools.<t>.approval_mode`; `auth`(oauth|chatgpt), `oauth{client_id,client_secret,callback_port,callback_url}`, `oauth_resource`, `scopes`; globals `mcp_oauth_callback_port|url`, `mcp_oauth_credentials_store`(auto|file|keyring). Note: TOML tables, not JSON; no `type` discriminator (inferred from `command` vs `url`).
- Hooks (`hooks.json` or `[hooks]`, gated by `features.hooks`): PreModelRequest, PostModelRequest, PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, SessionStart, SessionEnd, SubagentStart, SubagentStop, UserPromptSubmit, Stop, Interrupt; command and MCP-tool handlers only (prompt/agent parsed, skipped); keys `async, commandWindows, additionalContextLimit(2500 tokens)`. Payload/exit semantics not fetched.
- Skills (CDX build-skills): SKILL.md `name`+`description` required; optional `agents/openai.yaml` (`display_name, short_description, icons, brand_color, default_prompt, policy.allow_implicit_invocation, dependencies.tools`). Discovery: `$CWD/.agents/skills`, parent, `$REPO_ROOT/.agents/skills`, `~/.agents/skills`, `/etc/codex/skills`, bundled; symlinks followed; no ranking, same names not merged. Explicit `$name` / `/skills`; implicit by description. Disable via `[[skills.config]] path|name, enabled=false` (last match wins). Docs vs code gap: older Codex read `$CODEX_HOME/skills`; this page does not list it.

## 9. MCP (MCP spec 2026-07-28, "latest" at fetch time)
- Version string `2026-07-28` (previous 2025-11-25; HTTP+SSE since 2025-03-26 is Deprecated). A hypotaxis client must speak both eras: this revision is STATELESS: no `initialize`/`initialized`, no `Mcp-Session-Id`; every request carries `_meta` `io.modelcontextprotocol/protocolVersion`, `.../clientInfo`, `.../clientCapabilities`; servers implement `server/discover`; every result has `resultType` (`complete`|`input_required`); server-initiated requests (roots, sampling, elicitation) replaced by multi-round-trip `InputRequiredResult`/`inputResponses`; `subscriptions/listen` replaces GET stream and resource subscribe; `ping`, `logging/setLevel`, `notifications/roots/list_changed` removed; Roots/Sampling/Logging deprecated; results of list calls carry `ttlMs`, `cacheScope`; SSE resumability (`Last-Event-ID`) removed; tasks moved to extension `io.modelcontextprotocol/tasks`; "Skills over MCP" is an official extension. Fall back to initialize-based negotiation for older servers (Versioning page, not fetched in full).
- Transports: stdio (newline-delimited JSON-RPC over a subprocess; cancel with `notifications/cancelled`) and Streamable HTTP (each message a POST to one endpoint; reply JSON or request-scoped SSE; headers `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`, `Accept: application/json, text/event-stream`; cancel by closing the stream). Legacy HTTP+SSE: deprecated, keep for old servers.
- Authorization (OPTIONAL; HTTP only; stdio uses env): client MUST use RFC 9728 Protected Resource Metadata for AS discovery (from `WWW-Authenticate resource_metadata`), MUST support both RFC 8414 and OIDC discovery, MUST obtain a client id via CIMD (SHOULD support), pre-registration, or DCR (deprecated, MAY, must send `application_type`), MUST use PKCE and the RFC 8707 `resource` parameter in both authorization and token requests (canonical server URI, no fragment, prefer no trailing slash), MUST record issuer and validate RFC 9207 `iss` before redeeming the code (reject absent `iss` when AS advertises support), Bearer token in `Authorization` on EVERY request, never in query string, never send tokens not issued by the server's AS, key persisted client credentials by issuer, keep refresh tokens confidential; scope selection: `scope` from WWW-Authenticate, else `scopes_supported`; on 403 `insufficient_scope` do step-up with union of prior and challenged scopes, limited retries. (PKCE S256 requirement lives in the OAuth 2.1 draft and security-considerations page, not fetched.)

## 11. Precedence rules (proposed, derived from sources above)
1. Settings scalars: managed > CLI `--settings` > project-local > project > user; arrays union; deny > ask > allow regardless of source; security keys take stricter value. Managed tier: first source wins unless merge.
2. MemoryDoc: concatenate (never override): managed, user, then ancestors root->cwd, nested lazily; within a directory CLAUDE.md before AGENTS.md when both enabled; Codex: override file replaces sibling AGENTS.md; byte cap 32 KiB for Codex semantics (configurable per dialect).
3. Skills: managed > user > project (> nested/added dirs); plugin skills namespaced so no collision; skill beats same-named command; across dialects, when a dir holds both `.claude/skills` and `.agents/skills`, prefer native dialect then `.agents` (no source gives a cross-tool ranking: define and document it).
4. Subagents: managed > CLI > project > user > plugin. Output styles: nearest project dir > user, managed highest.
5. MCP: local > project > user > plugin > connectors, whole-entry replacement; managed outranks; project servers require approval; dedupe plugin/connector by endpoint.
6. Gemini: extension commands lowest, conflicts prefixed; project commands beat user. Cursor rules: Team > Project > User merged. Antigravity: workspace over global; rules cumulative.
7. Hooks: all sources additive (no override); run in parallel per event; any blocking decision wins (CC deny > ask > allow style) [parallel/any-block semantics for conflicting hooks UNVERIFIED].
8. Trust gating is part of precedence: untrusted repo content (project allow rules, plugins, MCP servers, Codex `.codex/`, Hermes project skills) must not activate until trust is granted.
